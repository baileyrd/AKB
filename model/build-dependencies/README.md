# Build-dependency projection

`current.json` is generated by `tools/import_build_dependencies.py` from the
MSYS2 repository databases. Do not hand-edit it.

It is **additive**: it contributes `build-depends-on` and `check-depends-on`
relationships and nothing else — no entities, no versions, no runtime edges.
That is what lets it carry a different observation date from
`model/catalog/current.json` without overwriting anything the catalog
observed.

An edge is emitted only when both endpoints already exist as packages in the
catalog projection. Edges naming a package the catalog does not hold are
dropped and counted, and the count appears in the projection's evidence record
and in the snapshot manifest under
`evidence/build-dependency-snapshots/<id>/`.

Regenerate with:

```
python tools/import_build_dependencies.py \
  --archive <path>/msys.db --repository msys \
  --archive <path>/ucrt64.db --repository ucrt64 \
  ...
```

The `.db` files are the pacman repository databases from `repo.msys2.org`.
They are Zstandard archives; the tool decompresses them with an external
`zstd`/`unzstd`/`bsdtar` if one is present, otherwise through `ctypes` against
the system `libzstd`. Neither route needs a package installed — see
[ADR 0002](../../charter/adr/0002-dependency-free-schema-checking.md).
